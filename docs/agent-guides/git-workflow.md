# Git and Pull Requests

Use the repository's Conventional Commit pattern with a scoped, imperative subject, for example `feat(draft): add publication recovery`, `fix(core): align types`, or `test(e2e): cover workflows`. Keep each commit focused on one coherent change.

In a pull request, explain the user-visible or operational behavior changed, link the relevant issue or implementation plan, and call out schema, migration, or configuration effects. State the commands used to validate the work. Include request/response examples or screenshots when API behavior or documentation changes materially.
